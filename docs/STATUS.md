## Known limitations

- The optional Python `modules/` tree is incomplete and is not bundled in the Electron package. Studio does not invoke it; affected capability handlers return `not_implemented` or `dependency_gated` with an explanation.
- The OAuth connection service is local encrypted persistence for verified connections. The host has real local callback, token-exchange, refresh and disconnect routes, exercised here against a test-only fake provider; its throttle is durable in the existing platform database when encrypted storage is available and falls back to an in-memory throttle only while that storage is unavailable. It has no live-platform approval, live publication path, or creator connection by default, and a platform is never reported connected without a stored verified record.
- The host AI task route performs guarded, read-only local model inference and fails closed with `503 ai_execution_not_ready` without a ready local model. It now stores durable owner-scoped task records and exposes list/detail reads, but it has no tools and no cloud fallback, so it is not a tool-using executor.
- Music playback routes through the Studio music mixer, but live platform output is still not verified here. Catalogue playback is fail-closed: the checked-in rights catalog is empty and the one seed track is `test-only`, so the Studio shows zero playable catalogue tracks until a local operator records exact, zero-cost evidence and supplies the audio file under `--music-root`. Locally picked audio files remain the user's responsibility.
- The game list in Studio is informational and comes from the read-only raw-data catalog; prototypes are not installed or launched from Studio.
- The Regie device-capability bridge now reports measured platform/architecture from Electron plus renderer/main-process probe evidence. Unmeasured features stay `limited`; a measured report is still not proof that a real camera, microphone, screen capture, or live broadcast works on a target device.
- The external program-output window renders a local scene canvas, not live video. Camera/screen sources are placeholders there; effects, encoder output, devices, platform login, and live publication are not bridged into that window.
- The raw-data catalog is seeded only from repository JSON. It has no write API, contains no TikTok gift IDs, and never reads the legacy `data/db` account databases.
- StreamioV-native gifts are free local effects. TikTok gifts remain in TikTok's own purchase and reward systems.
- The old `dist/streamiov-homepage` copy is not used by the host; the complete site is `dist/streamiov-homepage-worker/public`.
- The Studio declares no runtime npm dependencies. The unofficial `tiktok-live-connector` package was removed; any TikTok integration must use an officially approved interface.
- The public community forum is real but local-first. Threads, replies, abuse reports, and advisory spam flags are stored in a separate `forum.sqlite3`; anyone can read threads and replies, and writes require a host session, an exact same-origin request, JSON bodies, length validation, and per-IP rate limits. Reports and history are session-gated; spam flags are advisory only and never reject or delete posts. Operators can lock, unlock, soft-delete entries, list/history reports, and resolve or dismiss reports with the host CLI or, for IDs in `STREAMIOV_FORUM_MODERATORS`, the in-page `/forum/` queue. Moderation is fail-closed when no moderator IDs are configured. There are no email notifications; the documented local retention policy is applied explicitly by the operator CLI and never runs automatically.
- Password recovery by email is not implemented. The operator can create or reset a local account with the host CLI; there is no email delivery service.
- The source snapshot is a point-in-time copy. Because a file cannot contain its own archive checksum, the generated download metadata is not part of the archive; the live site under `dist/streamiov-homepage-worker/public/download/` is authoritative for the published parts and hashes. `tests/test_studio_js_syntax.py` verifies the live files byte-for-byte.
