# OpenCode Core desktop device client

## Current desktop client foundation

The optional `opencode-core-device` command provides a small native Python client
for Windows, macOS, and Linux. It uses the existing one-time enrollment endpoint
and stores the returned bearer token only in a verified operating-system vault:

- Windows Credential Vault (via the Windows keyring backend)
- macOS Keychain
- Linux Secret Service

Install the optional dependency with `pip install 'opencode-core[device]'`.
A supported vault must already be available and unlocked. Unknown, plaintext,
file-based, and fail backends are rejected; there is no file or environment
variable fallback.

Pair a device using a code generated by the signed-in account page:

```sh
opencode-core-device enroll --server https://core.example.com --code ONE_TIME_CODE --name "My laptop"
opencode-core-device status --server https://core.example.com
opencode-core-device forget --server https://core.example.com
```

The status command makes a fresh authenticated request each time, so it can be
run again after a network interruption. The token is never printed. The forget
command removes the local credential; it does not revoke the server-side device
record, which must be revoked from account device management.

## Security and capability boundary

- Remote servers require HTTPS; plain HTTP is accepted only on loopback.
- The one-time code is consumed by the server; the token is stored in the OS vault.
- The client currently receives only `status:read`.
- It cannot submit tasks, inspect queues, cancel workers, browse/edit workspaces,
  or access provider credentials.
- The client currently targets Windows, macOS, and Linux desktop environments.
  ChromeOS, Android, and iOS still require their own native secure-storage and
  lifecycle adapters; this Python client does not claim support for them.
- No automatic background daemon, push notifications, or unattended reconnect
  loop is enabled. Re-running `status` reconnects on demand.

A successful package build is not real-device certification. Each OS vault
backend must be verified on representative hardware before release.
